# 日常更新操作清单（SOP）

> 适用对象：内容运营 / 编辑
> 架构前提：单集合 + 双维度（场景 / 分类 / 标签）。**所有展示页均由一篇文章自动生成，你只维护"内容"本身。**
> 后台：Keystatic（GitHub 模式）→ 保存即提交 git → Cloudflare Pages 自动构建上线。

---

## 0. 一句话总纲

**日常你只做一件事：在「知识库文章」集合里写一篇文章，并给它打上「场景 / 分类 / 标签」三个维度。**
两个板块（场景聚合页、知识库分类列表、共用详情页）都是系统自动长出来的，你永远不用手写页面。

---

## 1. 角色与权限

| 角色 | 可操作 | 频率 |
|---|---|---|
| 内容编辑 | 写/改/下架「知识库文章」；打维度标签 | 日常 |
| 内容主管 | 维护「场景方案 / 分类管理 / 标签」三类词表；设 `featured` 首页展示 | 偶尔 |
| 开发者 | 改模板 / 组件 / 构建脚本（非内容） | 极少 |

---

## 2. 日常更新清单（每篇文章上线）

打开 Keystatic → 进入 **「知识库文章」** 集合 → 新建或编辑一条。

### 2.1 必填项
- [ ] **标题**（slug 字段）：英文、URL 友好，作为页面地址来源
- [ ] **展示标题**（中英双语 `name`）：卡片和详情页按当前语种显示
- [ ] **发布日期** `publishedAt`：日期选择器
- [ ] **已发布** `published`：勾选才会出现在站点（默认勾选；下架就取消勾选）
- [ ] **正文**：中文 / 英文双语正文

### 2.2 维度打标（核心 —— 决定文章出现在哪些板块）
- [ ] **所属场景** `scenario`（下拉，来自「场景方案」词表）：选「无」则不在任何场景页出现；选具体场景 → 出现在该场景页「相关内容」区
- [ ] **分类** `category`（下拉，来自「分类管理」词表）：决定它在知识库列表里的归类
- [ ] **标签** `tags`（多选，来自「标签」词表）：细粒度检索与关联推荐

### 2.3 增强项（影响 SEO / AI 抓取，建议都填）
- [ ] **在首页展示** `featured`：勾选则首页场景卡 / 文章流置顶（由主管控制）
- [ ] **常见问题** `faq`：问答数组 → 自动生成 FAQ 结构化数据，利于搜索/AI 直接抽取答案
- [ ] **自定义内容区块** `customSections`：按需插入标题/段落/图片/提示框/引用

### 2.4 保存即上线
- [ ] 点保存 → Keystatic 自动提交到 GitHub `main` 分支
- [ ] GitHub Actions（`.github/workflows/deploy.yml`）自动构建并部署到 Cloudflare Pages
- [ ] 约 1–2 分钟后在线上看到新文章（Cloudflare 边缘缓存可能短暂返回旧页，加 `?cb=时间戳` 强制刷新核验）

> ⚠️ 后台改完**不会立即生效**，必须等构建完成。这是静态站点的正常表现，不是 bug。

## 3. 受控词表维护（偶尔，仅主管）

三个维度选项都来自"词表"，**新增维度值只在词表里加一次**，之后文章才能选到。

| 词表 | Keystatic 位置 | 存储 | 改完效果 |
|---|---|---|---|
| 场景方案 | 「场景方案」集合 | `src/content/scenarios/*.yaml` | 场景页、下拉选项自动更新 |
| 分类管理 | 「分类管理」singleton | `categories/index.yaml` | 分类下拉、知识库归类更新 |
| 标签 | 「标签」singleton | `tags/index.yaml` | 标签多选、检索更新 |

**新增一个场景的完整步骤：**
1. 进「场景方案」集合 → 新建 → 填标题 / 展示标题 / 一句话结论 / 选型逻辑（驱动 HowTo）/ FAQ / 推荐产品占位
2. 保存（提交 git，自动构建）
3. 之后在「知识库文章」里就能选到这个新场景；对应场景聚合页自动生成

> 受控词表 = 下拉选项，编辑**无法手敲**新值，从根上杜绝 `scenario-a` vs `scenarioA` 拼写漂移。

---

## 4. 自动化生成清单（你**不用**动）

以下全部由构建期从「知识库文章」聚合生成，请勿手动编辑：

- 场景聚合页 `/scenarios/[slug]` 及页内「相关内容」
- 知识库列表 `/knowledge/` 及按分类的归类
- 共用详情页 `/knowledge/[slug]`（两个入口同一链接）
- 筛选 / 搜索 / 选型向导前端组件（纯静态，数据驱动）
- `sitemap.xml`、`llms.txt`、结构化数据（Article / FAQPage / HowTo）
- 维度下拉选项（由 `scripts/gen-content-options.mjs` 在 prebuild 阶段从词表 codegen 到 `src/generated/content-options.ts`）

---

## 5. 质量闸门（上线前自动拦截）

| 闸门 | 作用 | 触发 |
|---|---|---|
| 构建期校验 `build-checks` | 文章引用了不存在的场景/分类 slug → 构建直接失败 | `astro build` |
| 受控词表 codegen | 下拉选项永远与词表一致 | prebuild |
| 质量分 / 新鲜度（L4，规划中） | 缺结论/缺 FAQ/超 180 天未更新 → 标记待审 | 构建期统计 |

> 编辑视角：只要能保存成功且构建通过，内容就合法。构建失败会在 GitHub Actions 日志里报具体哪篇、哪个字段。

---

## 6. 运营轻维护（规划层，占用极少精力）

| 层 | 你要做的 | 频率 |
|---|---|---|
| L4 信任（新鲜度） | 修订文章时顺手更新 `publishedAt` / 补 FAQ | 随写文 |
| L7 反馈（有帮助投票） | 定期看冷热报表，把"无帮助"多的文章列入修订 | 周/月 |

用户投票是**他们产生**的数据，你只读报表、不写内容。

---

## 7. 常见操作速查

| 需求 | 怎么做 |
|---|---|
| 让文章在两个板块都出现 | 同时填 `scenario` + `category`，都别留「无 / 未分类」 |
| 只在知识库出现、不进场景页 | `scenario` 选「无」，`category` 正常填 |
| 下架一篇文章 | 取消 `published` 勾选（保留数据，可随时恢复） |
| 改文章归类 | 改 `scenario` / `category` / `tags` 任一项 → 两个板块同步变 |
| 新增一个分类 | 进「分类管理」singleton 加一项 → 保存 |
| 新增一个标签 | 进「标签」singleton 加一项 → 保存 |
| 让文章上首页 | 由主管勾 `featured` |
| 改了后台没变化 | 等 1–2 分钟构建；用 `?cb=时间戳` 破缓存核验 |

---

## 8. 故障与回滚

- **构建失败**：看 GitHub Actions 日志 → 通常是词表漂移或字段缺漏 → 修对应文章/词表 → 重新保存触发构建。
- **内容错了要回退**：Keystatic 走 git，直接 `git revert` 对应提交或后台改回，重新构建即可。
- **紧急撤下**：取消 `published` 勾选最快，无需删数据。

## 附：日常心智模型

```
写文章 ──┐
打标签 ──┼──► 知识库文章（唯一数据源）──► 构建期自动分发到：
         │        │                       • 场景聚合页
         │        │                       • 知识库分类列表
         └────────┘                       • 共用详情页
                                            • sitemap / llms.txt / 结构化数据
                                            • 筛选 / 搜索 / 向导 UI

词表（场景/分类/标签）──► 只在"新增维度值"时动，日常发文不动。
```

**记住：你只对一个集合负责。其余都是系统替你做的。**
